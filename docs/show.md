# «Лига знаний»: учебное 3D-шоу

Новый режим использует существующие аккаунты, ASP.NET API, движок начисления XP, Prisma и SQL Server. Откройте пункт «Лига знаний · 3D-шоу» в меню студента или адрес `http://localhost:8080/#show` после входа. Разделы курсов, рейтинга, достижений, статистики, администрирования и существующий сетевой режим сохраняются.

## Запуск с SQL Server

База остаётся под управлением SQL-скриптов для SSMS; контейнеры не применяют схему и не заполняют рабочую базу автоматически.

1. Для новой базы выполните `database/sqlserver/01_CreateGamifiedLearningSystem.sql` в SSMS. Для уже настроенной базы повторять создание не требуется.
2. В нужной базе выполните `database/sqlserver/03_ShowSessions.sql`. Это повторяемое дополнение: `Tasks.content` и таблица `ShowSessions`; существующие курсы и прогресс сохраняются.
3. Настройте доступ и переменные из `.env.example` по инструкции в `README.md`. При необходимости создайте SQL-логин скриптом `02_CreateApplicationLogin.sql`, подставив собственный пароль. Реальные секреты не должны попадать в репозиторий.
4. Подготовьте клиент Prisma и наполните учебный банк:

```powershell
# Из корня проекта
. ./scripts/Import-Environment.ps1
Set-Location PrismaService
npm ci
npm run generate
npm run build
npm run seed
```

Для разработки откройте три терминала из корня проекта:

```powershell
# Терминал 1: закрытый сервис данных
. ./scripts/Import-Environment.ps1
Set-Location PrismaService
npm run dev

# Терминал 2: публичный API
. ./scripts/Import-Environment.ps1
dotnet run --project Backend/GamifiedLearningSystem.API --urls http://localhost:5080

# Терминал 3: клиент
Set-Location Frontend
npm ci
npm run dev
```

Откройте `http://localhost:8080`. Для Docker после обновления схемы и заполнения базы используйте `docker compose up --build`. Сервис данных на порту 4000 предназначен для обращения из API и требует `DATA_SERVICE_KEY`; браузер работает через `/api`.

## Короткая демонстрация

1. Зарегистрируйте студента или используйте учебный аккаунт из seed: `student@example.com`, пароль `Student123!`. Эти реквизиты предназначены для локального демонстрационного стенда.
2. Откройте шоу, выберите Нову, Лео, Майю или Атласа. Ведущий — Марк.
3. Выберите курс «Информатика: от алгоритма к данным», тему «Все темы» и начните эфир.
4. После вступления нажмите начало первого задания. Серия состоит из 10 заданий и пяти видов раундов. После каждого ответа посмотрите реакцию персонажей, объяснение, очки шоу и отдельно заработанный XP; затем переходите дальше.
5. Для составления последовательности нажимайте элементы в нужном порядке; выбранный элемент можно убрать. При сопоставлении выберите разные пары для всех строк. Для числовой задачи введите число; десятичная точка и запятая поддерживаются. В выборе ответа доступны мышь, сенсорный экран и клавиши 1–4.
6. Попробуйте подсказку, настройку громкости и уменьшение движения. Меню настроек не останавливает таймер.
7. Перезагрузите страницу во время задания: текущая серия и серверный срок ответа восстановятся. Истёкшее время приводит к завершению вопроса с неверным ответом, а не к новому таймеру.
8. Завершите финал: на экране появятся победитель, итоговые места, число правильных ответов и XP. Затем откройте статистику, достижения, ежедневные цели и рейтинг.

В одиночном шоу соперники помечены как боты: Тактик, Спринтер и Исследователь. Их вероятность правильного ответа и время реакции различаются; высокая сложность снижает точность. Боты не являются студентами и не попадают в учебный рейтинг. Дуэль автоматически выбирает лидирующего бота в начале двух заданий дуэли.

## Правила очков

| Раунд | Заданий | Время на задание | Очки шоу |
|---|---:|---:|---|
| Классический | 2 | До 35 с | 100 за правильный ответ |
| На скорость | 2 | До 22 с | 100–250 за правильный ответ; быстрее — больше |
| Ставка | 1 | До 35 с | Ставка от 0 до min(300, текущие очки); правильно: 100 + ставка; ошибка: −ставка |
| Дуэль | 2 | До 30 с | 150 за правильный ответ; ещё 75 за самый быстрый правильный ответ против выбранного соперника |
| Финал | 3 | До 40 с | 200 за правильный ответ; подбор стремится к более высокой сложности |

Длительность ограничена также лимитом самого задания. Очки шоу определяют место только в текущей серии. Положительную ставку нужно подтвердить до ответа: она сохраняется на сервере, затем не меняется и учитывается даже при тайм-ауте. Неподтверждённая ставка считается нулевой. Проигранная ставка не уменьшает накопленный учебный XP.

Учебный XP начисляет существующий `GamificationEngine`. Для демонстрационного банка базовая награда `EASY` — 80 XP, `MEDIUM` — 120 XP, `HARD` — 180 XP. При первом успешном прохождении ранее не завершённого задания:

```text
TASK XP = базовая награда + бонус первой попытки
бонус = 50% базовой награды, если это первая попытка и подсказка не использовалась;
        иначе 0.
```

Поэтому правильный первый ответ без подсказки даёт 120, 180 или 270 XP соответственно. После ошибки или подсказки первое успешное завершение даёт только базовую награду. Ошибка и тайм-аут не дают награды `TASK`; уже завершённое задание никогда не даёт повторную награду `TASK`, включая другие серии шоу. Скорость сама по себе не меняет эту формулу, но может открыть достижение.

К награде за задание сервер добавляет впервые открытые достижения из seed (по 300 XP), впервые выполненную за день цель «3 разных задания» (200 XP) и бонус серии дней. Бонус серии доступен с третьего последовательного учебного дня: `min(currentStreak × 10, 100)` XP, один раз в новый день при успешном завершении нового задания. Повтор одного задания не увеличивает ежедневную цель или серию дней. Полный заработок ответа — сумма новых наград `TASK`, `ACHIEVEMENT`, `DAILY_GOAL` и `STREAK`; все они отражаются в истории XP.

Сервер хранит состояние серии в SQL Server. При отправке ответа одновременно сохраняются попытка, XP, учебный прогресс и очки шоу. Повторная отправка с тем же идентификатором запроса возвращает уже сохранённое состояние. Владение серией определяется аккаунтом из JWT. Клиент не передаёт правильный ответ или размер награды.

## Учебный банк и адаптация

`PrismaService/prisma/show-bank.ts` содержит 36 вручную составленных и проверенных заданий: по 12 на темы «Алгоритмы и логика», «Представление данных», «Базы данных и безопасность». В каждой теме есть все четыре формата на каждой из трёх сложностей. Всего: 9 заданий выбора ответа, 9 последовательностей, 9 сопоставлений и 9 числовых задач; по 12 заданий начальной, средней и высокой сложности. В объяснениях приведены вычисления или правило, обосновывающее ключ.

Курс добавляется к трём существующим курсам и их 75 заданиям. Его единственный демонстрационный уровень «Открытая студия» имеет порог 0 XP, поэтому новая учётная запись сразу может пройти серию со всеми форматами. В существующих курсах сохраняется последовательное открытие уровней и их пороги XP.

Адаптация шоу выполняется локально по проверенному банку. Три правильных ответа подряд повышают учебную сложность на одну ступень; две ошибки подряд снижают её на одну ступень. Повторные повышения происходят на кратных трём верных ответах серии, понижения — на кратных двум ошибках; границы — `EASY` и `HARD`. Финал целится на одну ступень выше текущей учебной сложности, сохраняя верхнюю границу `HARD`, и выбирает ближайшую доступную ступень.

Подбор также учитывает доступные уровни, выбранные курс и тему, повторные ошибки, время ответа, подсказки, слабые темы и требуемый формат раунда. Причина выбора сохраняется в `AIRecommendation` с источником `fallback` и отображается игроку. Генеративная модель для работы шоу не требуется; этот подбор не создаёт непроверенных заданий. В небольшом банке возможны повторения после исчерпания доступных заданий.

Публичное поле `Task.content` хранит только данные взаимодействия. Для `SEQUENCE` это `{ "items": [...] }`; ключ — JSON-массив в `correctAnswer`. Для `MATCHING` это `{ "left": [...], "right": [...] }`; ключ — JSON-объект соответствий. Для `NUMERIC` это `{ "unit": "...", "tolerance": 0 }`; ключ — строка с числом. В выборе ответа используются существующие `TaskOption`. Правильный ответ и объяснение появляются в результатах только после завершения текущего задания.

Личная статистика дополняется средним временем: среднее `Attempt.timeSpent` по сохранённым попыткам, включая ошибки и тайм-ауты, округляется до 0,1 секунды. Сильная тема требует минимум трёх попыток и точности от 80%; тема для повторения — минимум трёх попыток и точности ниже 60%. Пока данных недостаточно, тема не назначается. Результаты относятся к наблюдаемым попыткам и не являются оценкой всех знаний студента.

## Проверки

```powershell
dotnet build GamifiedLearningSystem.sln
dotnet run --project Tests/GamifiedLearningSystem.Tests
Set-Location PrismaService
npm run build
npm run test:show-bank
npm run test:show-rules
Set-Location ../Frontend
npm run build
```

`test:show-bank` проверяет полноту банка, уникальность вариантов, JSON-контракты, числовые ответы независимыми вычислениями, границы битовых диапазонов, трассировку циклов, порядок зависимостей и повторяемость seed без изменения прежних курсов. Отдельно проверяются статистика при пустой истории, недостаточное число наблюдений и среднее время. Эти проверки и `test:show-rules` не подключаются к рабочей базе.

Полное прохождение через API и браузер проверяется отдельно на уже запущенном локальном стенде с SQL Server, применённым `03_ShowSessions.sql`, собранным сервисом данных и seed. Проверки создают новые тестовые аккаунты и записывают их учебный прогресс:

```powershell
# Из корня проекта, после запуска всех трёх сервисов
node scripts/verify-show-server.mjs
Set-Location Frontend
$env:RUN_SHOW_E2E = '1'
npm run test:show
Remove-Item Env:RUN_SHOW_E2E
```

Без `RUN_SHOW_E2E=1` браузерные проверки живого стенда пропускаются. На Windows конфигурация использует установленный Microsoft Edge; в CI — Chromium Playwright.

Проверка реального перезапуска также использует новый тестовый аккаунт. Первый шаг проходит первые четыре задания и подтверждает ставку 100 очков на пятом. Затем остановите и снова запустите только API и сервис данных обычными командами запуска; второй шаг проверяет сохранённую серию после нового входа и завершение по исходному сроку:

```powershell
# Из корня проекта при запущенном стенде
node scripts/verify-show-persistence.mjs --prepare
# Остановите и снова запустите API и PrismaService.
node scripts/verify-show-persistence.mjs
```

Второй шаг при необходимости ждёт до первоначального дедлайна, проверяет потерю подтверждённой ставки при тайм-ауте и завершает тестовую серию. Отчёт сохраняется в `artifacts/show-persistence-report.json`.

Проверено 12 октября 2026 года: 41 доменный тест, 9 тестов банка и статистики, 12 тестов правил шоу — PASS. На реальном API и SQL Server пройдена полная серия из 10 заданий: все пять раундов и все четыре формата, проверка владения серией, сохранение состояния, подтверждение ставки и отсутствие повторного начисления XP. Четыре браузерные проверки — полная игра, мобильный вопрос, студия и выход во время загрузки — PASS. При 390 × 844 все четыре ответа доступны, вопрос и результаты не создают горизонтальной прокрутки. Все 12 прежних интеграционных проверок авторизации, переводов, администрирования и SignalR-мультиплеера тоже проходят. Серверный отчёт находится в `artifacts/show-server-report.json`.

Проверка студии — PASS: пять людей с деформируемыми скелетными моделями, 12 обязательных действий персонажей и ведущего, движение костей, выход на сцену, переключение качества и уменьшение движения, ошибка отсутствующего манифеста и освобождение сцены. Отчёт — `artifacts/show/studio-report.json`.

Восстановление после фактической остановки и перезапуска API и сервиса Prisma — PASS: новый вход вернул тот же матч и пятое задание, срок ответа сохранился, тайм-аут списал подтверждённую ставку 100 очков шоу, учебный XP остался прежним (1640 XP). Результат зафиксирован в `artifacts/show-persistence-report.json`.

В последнем сохранённом коротком контрольном прогоне получено 110,03 FPS за 2208 мс при среднем качестве и разрешении 1440 × 1000; параллельно выполнялись проверки прежнего интерфейса в другом браузере. Среда: Edge 155, Windows 10, Intel UHD Graphics (`0x46A3`), WebGL 2.0. Браузер сообщает 12 логических потоков через `hardwareConcurrency`; модель устройства и процессора не определялась. Это короткий контрольный замер, а не гарантия производительности всех ноутбуков; последующие прогоны могут отличаться.

## 3D-модели и анимация

Студия работает на Three.js 0.180.0. Локальный манифест `Frontend/public/assets/characters/manifest.json` сопоставляет персонажей с моделями: Нова — `femaleCasual`, Майя — `femaleFormal`, Лео — `maleHoodie`, Атлас — `maleCasual2`, ведущий Марк — `maleSuit`. Используется комплект объёмных людей со скелетом из Quaternius Ultimate Modular Men/Women, распространяемый по CC0. Происхождение файлов и условия использования описаны в `Frontend/public/assets/ASSETS.md`; лицензия Three.js сохранена в `Frontend/public/assets/THREE-LICENSE.txt`. Для запуска модели должны находиться на локальном сервере; внешняя CDN не требуется.

Сохранены исходные анимации ожидания и ходьбы. Жесты размышления, нажатия кнопки, радости, ошибки, победы и поражения, а также действия ведущего созданы как анимационные клипы костей; переход между клипами длится 0,3 секунды. Реакции привязаны к состоянию задания и результату сервера. Анимации речи через лицевые blendshape и синхронизация губ с озвучкой не реализованы. При отсутствии модели или манифеста загрузчик показывает ошибку и возможность повторить загрузку; геометрическая фигура не выдаётся за готового персонажа.

## Границы текущего режима

3D-шоу — одиночная серия против трёх ботов. Существующий раздел «Мультиплеер» остаётся отдельным сетевым квизом через SignalR; это не совместная 3D-студия. Новый учебный банк и реплики шоу написаны на русском; существующие переводы остального приложения сохраняются. Звук синтезируется в браузере; все игровые реплики доступны в текстовом виде. Состояние серии сохраняется на сервере, но отсчёт не приостанавливается при закрытии вкладки.
